预填充兼容

预填充兼容模式
什么是预填充 ：请求里 最后一条 assistant 消息 （酒馆预设里通常是最底部那条“助手”条目，内容多为思维链的开标签）。它替模型写好了回复开头，模型只能顺着往下写——这是破限最强的杠杆，也用来顶掉原生思维链。预设里那些 system 条目 不是 预填充。
为什么需要兼容 ：Gemini 3.x 拒绝以 assistant 结尾的请求（400），必须改造成 user 结尾。

智能（默认） ：删掉那条 assistant，把它的文字并进最后一条 user。模型视角＝“用户给了我一段参考文字”。输出干净（实测开闭标签各 1 个），但模型没有“说过”这句话，破限杠杆最弱。
保留模型轮次 ：assistant 原样留着，后面补一句很短的 user 推动语。模型视角＝“这是我自己写了一半的”，破限杠杆保留。代价是模型容易当成新一轮、 把开标签再写一遍 （实测 3/3）。
最小 ：只补占位 user 保证不报错， 不把预填充拼回输出 ——思考开标签会缺失，前端正则可能抓不到。
关闭 ：原样发出，3.x 直接 400；而且代理检测不到预填充，思考压制也不会触发。

2.5 及更早的模型不受影响，走的是 原生透传 ，效果等同老式预填充。
预填充时压制原生思考
检测到预填充时，把模型的 原生思维链压到最低并不回传 ，让预设自带的思维链接管（写作效果通常更好，也避免“只有思考没有正文”）。
3.x 压到最低档（无法完全关闭），2.5-flash 预算 0 全关，2.5-pro 降到 128。
只在请求真的带预填充时才触发 ；若你的预设把思维链写在 system 里、没有 assistant 条目，请改用上方“思考强度”卡片的“关闭原生思考”。
仅保存全局运行设置。模型行为请使用上方保存按钮。
