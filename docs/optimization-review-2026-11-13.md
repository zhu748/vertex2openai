## 已修复的问题

| 级别 | 问题与触发条件 | 修改后的行为 | 主要位置 |
| --- | --- | --- | --- |
| P1 | 事件循环繁忙时，日志每条调用一次 `call_soon_threadsafe`；asyncio 队列有界，但队列前的回调及其消息引用持续增长 | 工作线程先写有界交接缓冲，每订阅者最多一个待执行回调，批量投递最新消息 | `app/log_stream.py` |
| P2 | 媒体与文本执行器共用 32 份准入名额，媒体满载时空闲的文本执行器也会拒绝任务 | 执行器与准入名额一一对应；其他入口预算有余量时，媒体满载不会单独阻止文本准备 | `app/media_tasks.py` |
| P2 | 续传整包响应仅为计算字节数，就执行整份 `json.dumps().encode()`，产生额外的大对象并同步占用事件循环 | 复用分块编码器精确计数；超过 1 MiB 的估算规模在线程执行，取消计量时仍允许缓冲进入错误终态 | `app/json_encoding.py`、`app/resumable.py` |
| P2 | 关闭 `request_diagnostics` 后，非流式观察器仍缓存正文，最多约 2 MiB/观察器 | 直接累计接收或发送字节，不再保留未使用的正文副本 | `app/request_tracking.py` |
| P3 | 纯模型目录规则位于抗截断传输模块，原生目录另行拼装相同的搜索和分辨率变体 | 提取 `model_catalog.py`，标准变体统一展开；原生目录仍按其协议能力发布条目 | `app/model_catalog.py` |
| P3 | 日志订阅、跨线程调度和全局 print 钩子混在同一模块；架构文档还描述旧的逐文件测试进程 | 日志投递归独立模块；新增依赖方向检查，修正文档并建立测试分类索引 | `app/logger.py`、`scripts/check_architecture.py`、`tests/README.md` |

之前已完成的 Hydrogen 修复同时保留：默认远程清单和备用 CDN 都指向
`zhu748/vertex2openai`。Render 的显式 `MODELS_CONFIG_URL` 环境变量仍优先于代码默认值。

## 性能复现与测量

环境为 Python 3.12，使用仓库锁定依赖。内存单位为 MiB，1 MiB = 1,048,576 字节。
`tracemalloc` 统计 Python 分配，不代表容器全部 RSS。

### 日志积压

单订阅者、队列容量 500，事件循环暂不执行投递回调；生产者连续提交
20,000 条约 1 KiB 的不同消息。测量结束后继续投递，验证保留的最新 500 条顺序正确。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 待执行投递回调 | 20,000 | 1 |
| 积压阶段保留分配 | 25,831,056 字节（24.63 MiB） | 590,428 字节（0.56 MiB） |
| 最新消息交付 | 最新 500 条 | 最新 500 条 |

这是事件循环积压场景的局部测量，不据此推断模型生成时间或正常流量吞吐。
修改后的场景可重复运行：

```sh
python scripts/benchmark_log_delivery.py
```

### JSON 字节计量

响应包含一个 8 MiB 的 ASCII 内容字段。两种方式都计算出 8,388,651 字节，
计量开始前已构造输入，不把原始响应自身计入额外分配。

| 方式 | 计量时峰值额外分配 |
| --- | ---: |
| 整份 `json.dumps().encode()` | 18,875,412 字节（18.00 MiB） |
| 分块编码计数 | 266,536 字节（0.25 MiB） |

完整 `ResumableBuffer.finish()` 的同场景测量也从 18,875,748 字节降到
276,902 字节。控制字符、中文、emoji 与字节预算恰好相等/相差一个字节的情况由回归测试验证。

可重复比较两种计量方式：

```sh
python scripts/benchmark_json_accounting.py
```

## 分类与维护边界

| 层次 | 归属 | 修改约束 |
| --- | --- | --- |
| HTTP 入口 | `app/routes/` | 鉴权、协议错误形状、路由装配 |
| 上游及交付 | `app/upstreams/`、`channel_dispatch.py` | 网络请求、重试、流式状态和通道切换 |
| 目录和编码规则 | `model_capabilities.py`、`model_catalog.py`、`json_encoding.py` | 模型规则、变体展开、编码与计量；目录层不反向依赖路由或传输 |
| 资源与生命周期 | `media_tasks.py`、`client_pool.py`、`lifecycle.py`、`resumable.py` | 准入、租约、任务取消、连接回收和预算 |
| 可观测性 | `request_tracking.py`、`log_stream.py`、`logger.py` | 分别管理请求诊断、跨线程日志交付、输出与统计 |
| 状态和配置 | `runtime_state.py`、`config.py` | 快照、原子落盘、修订和默认值 |

旧的 `logger.SSELogger` 和 `anti_truncation` 目录函数导入仍可使用，应用内的新目录
调用已指向所属模块。依赖检查阻止目录或日志模块重新导入其上层适配器。
测试分类与定向命令见 `tests/README.md`，架构说明见 `docs/architecture.md`。

文本与媒体仍各使用 8 个线程；本轮没有增加线程数。各执行器最多接受 32 个
运行/排队任务，合计上界 64，生成请求仍受入口请求数、正文总字节和结构预算限制。
等待者取消后，名额在实际线程退出时归还；执行器提交失败也会归还对应名额。

## 后续优化的取舍

以下项目需要独立的行为设计或实际流量测量：

- 完整 JSON 交付仍构造最终 `.body`，续传和多协议适配有直接读取该属性的调用者。
  真正流式编码需要一起修改这些消费方以及取消、错误、统计和重放契约。
- `native_passthrough._passthrough_request_impl`（255 行）、
  `SDKGeneration._emit_attempt_frames`（233 行）及 Cookie 收集/交付方法仍较长。
  后续拆分应围绕准备、尝试、终结与资源所有权，先选定一个管线并保留交付回归。
- 大量自定义模型覆盖时，应进一步测量每模型生效设置缓存保留完整配置树的成本；
  共享修订快照需要明确嵌套配置的只读约束与复制边界。

本轮验证为本地离线与模拟上游测试，未调用真实 Google 模型、部署到 Render，
也未执行 Docker 镜像构建、Go 编译/race 或真实浏览器布局检查。前端脚本、Go 代码、
依赖版本和 Dockerfile 本轮均无修改。
