# 控制台配置与布局更新

本次更新将模型行为与运行设置拆为独立页面，让模型覆盖按字段保存，并明确所有配置的生效方式。控制台仍然由本地 HTML、CSS 与原生 JavaScript 提供，生产环境不需要 Node.js。

## 主要问题与调整依据

| 原有问题 | 使用影响 | 本次调整 |
| --- | --- | --- |
| 模型保存提交全部参数 | 只改一个字段也会固定其他继承值，之后全局修改不再生效 | 按字段保存、显示来源、逐字段恢复继承 |
| 模型行为和服务运行参数集中在一页 | 页面过长，难以判断保存范围和关联设置 | 拆分页面，将超时、并发、续传缓冲按用途分组 |
| 调度策略入口重复，分区保存反馈不足 | 容易误判哪些修改已生效，重载可能覆盖草稿 | 保留单一即时入口，加入分区状态、撤销和离开提示 |
| 凭证表单全部展开 | 多账号下内容密集，查找成本高，Key 常驻可见 | 默认收起、摘要搜索、启用状态筛选和 Key 显隐 |
| 手机导航和表单操作分散 | 切页及长页面保存不方便，部分控件文字偏小 | 页面选择器、单列配置、底部保存条和更大触控目标 |
| 监控表格列多且频繁替换节点 | 阅读和选择内容易被刷新打断 | 核心列默认展示、详细列开关、暂停刷新和行节点复用 |
| 累计概览难以反映近期状态 | 排查当前失败和延迟时缺少直接入口 | 增加近 15 分钟保留样本指标，并注明统计边界 |
| 帮助和错误反馈不一致 | 部分说明无法展开，错误提示消失后难以定位 | 同步展开状态、持久字段错误和焦点定位 |

## 页面与操作

- **数据概览**：累计计数之外增加近 15 分钟保留样本的成功率、首回复 P50/P95、通道计数与失败入口；提供 OpenAI Base URL 复制和首次接入说明。
- **通道与凭证**：账号摘要默认收起，显示备注、项目和凭证尾号；支持搜索、启用状态筛选、显隐 Key、局部撤销和列表底部保存。指纹配置移入高级折叠区。
- **模型参数**：每个字段标明继承全局、继承内置或模型专属。修改单字段仅保存该字段；可单独恢复继承，或清除全部专属。切换模型保留内存草稿。首回复超时归入超时与抗截断传输。能力不支持的选项禁用，非生图模型默认收起生图设置。
- **运行设置**：超时、并发和续传缓冲放在同组；交付、图片压缩、保活、兼容设置按任务排列。底部保存条固定在本页范围内，显示未保存状态并提供撤销。
- **请求监控**：默认显示核心列，详细列按需开启；手机初次加载每页 10 条，可切换条数；支持暂停/恢复自动刷新。列表按请求 ID 更新，保留未变化的行节点。
- **运行日志**：保留已有日志搜索、级别筛选、关联请求详情和自动滚动行为。

手机使用明确的页面选择器，配置卡片在 960px 以下采用单列；手机模型保存操作移至分区底部。重要辅助文字加深，触控目标和输入字号统一。帮助展开同时维护实际可见性和 ARIA 状态。

## 保存与继承

通道选择和账号调度是明确标注的即时保存；账号、代理、模型和运行配置采用分区保存。账号调度只保留通道页入口。未保存的修改会在刷新/离开页面时提示，普通页签切换保留草稿。代理弹窗中的草稿也纳入离开保护。凭证草稿不写入 localStorage 或其他浏览器持久存储。

模型保存 API 保持原有扁平 patch 格式，增加可选 `_inherit` 字符串数组：

```json
{"first_reply_timeout_seconds": 35, "_inherit": ["thinking_g3_level"]}
```

该操作只覆盖超时，并移除已保存的思考档位，使其重新继承。`null` 仍表示“不注入默认值”，不承担删除语义。同一字段不能同时赋值并恢复继承；无效请求整体拒绝。内置模型默认不会因为恢复继承而丢失。能力接口增加 `saved_overrides` 与 `builtin_overrides`，用于准确说明参数来源。

已有版本保存的完整模型覆盖不会自动删减，因为无法判断哪些值是用户有意固定的。可以使用逐字段“恢复继承”整理，或者清除该模型全部专属配置。

## 近期统计的口径

`GET /api/recent-metrics` 需要控制台会话。统计近 15 分钟接收、当前进程仍保留的主请求；排除续传读者，取消请求不计入成功率。延迟百分位仅使用已收到首回复的样本。记录受现有数量、时长和字节限制，重启与回收可能导致样本不完整，页面明确提示这一点；这些数据不能代替持久化监控或 SLA 报表。

## 开发与验证

```bash
pip install -r requirements-dev.txt
python scripts/check_project.py
npm ci
npm run test:console
npm run build:css
npx playwright install chromium
npm run test:browser
```

`npm run test:console` 使用 jsdom，覆盖保存负载、继承恢复、能力控制、草稿状态、字段校验、账号列表、请求节点复用和刷新控制。它不模拟真实布局。浏览器套件单独检查 320/390/768/1024/1440px、表单提交、代理导入和请求详情。`PLAYWRIGHT_CHROMIUM_EXECUTABLE` 可指定浏览器，`UI_TEST_CJK_FONT` 可提供本地中文字体。

本次执行环境中 Python 回归和 DOM 交互检查可运行，Chromium 进程无法启动。因此真实浏览器的视觉布局、触摸键盘和端到端浏览器套件仍需在可用的浏览器环境复核。

## 仓库恢复

完整 Git 备份包含基线与 `feat/console-usability-overhaul` 分支，恢复方式：

```bash
git clone vertex2openai.bundle vertex2openai
git -C vertex2openai switch feat/console-usability-overhaul
git -C vertex2openai remote set-url origin https://github.com/zhu748/vertex2openai.git
```

备份只包含 Git 已跟踪的源码及历史，不包含运行凭证、测试依赖或浏览器二进制。
