## 已实施改进

### 1. 长工具参数减少整树复制

原实现将合并后的整棵参数树进行 `json.dumps(ensure_ascii=True)` 与 `json.loads`
往返，只为折叠可能跨分片出现的 UTF-16 代理项。大量中文因此先膨胀成 ASCII 转义，
再构造一份新对象，之后响应适配器还会再次编码参数。

现在直接构造结果树，仅对实际包含代理项的字符串或键做 Unicode 归一化。
最近使用的 JSONPath 只保留一份解析结果，连续字符串分片不再重复解析相同路径。
缓存仅限单次调用的最近一路径，没有新增全局无界缓存。

未配对代理项、NaN/Infinity、未完成字符串、重复字段、数组缺口和无效路径继续明确失败。

主要文件：`app/tool_stream.py`。

### 2. 修复 GraphQL 空默认字段误报冲突

例如一个有效字符串分片也可能带上 `numberValue: null`、`boolValue: null`、
`nullValue: null`。原实现会把最后一个空默认字段视为第二个实际值，误报 oneof 冲突。

现在优先识别实际字符串、数字和布尔值，并正确处理带空默认字段的字符串终止分片。
真正的 `NULL_VALUE` 与另一实际值同时出现时仍拒绝；`0`、`false` 和有效 null 均保留。

主要文件：`app/tool_stream.py`；新增回归覆盖完整 Cookie 分片合并链。

### 3. 请求监控只复制当前页

原实现无论每页显示多少条，都会在全局注册表锁内为所有记录复制完整公开快照和全部时序字典。
记录较多时，这会占用内存，并阻塞新的请求登记。

现在先保存记录引用，释放全局锁后读取每条记录的少量标量，完成筛选、汇总和活动请求优先排序。
只对最终页内记录生成完整快照。分页、搜索、总数和全局活跃汇总语义保持一致。

并发回归将页内快照故意阻塞，同时验证新请求仍可登记。

主要文件：`app/request_tracking.py`。

### 4. 随机选 Key 省去整池打乱

原实现对所有候选执行安全随机 shuffle，最终只消费第一个元素。
现在直接用同一 `SystemRandom` 的 `choice` 选取一项，省去逐条乱序需要的随机数与交换操作。
候选过滤仍为线性扫描；硬排除、失败 Key 软回避和单 Key 继续重试的行为均保留。

主要文件：`app/express_key_manager.py`。

### 5. 图片每跳只进行一次 DNS 解析校验

原实现先检查域名，然后为实际固定 IP 再解析一次；每次有效重定向也重复这一过程。
现在在每跳取得并校验地址后，直接向该地址发送请求，继续使用原域名的 Host 与 TLS SNI。
初次私网地址仍在创建客户端前拒绝，重定向目的地继续逐跳检查。

没有重定向时解析从两次降为一次；一个有效重定向的测试中，解析从四次降为两次。
DNS 重绑定回归验证：即便下一次 DNS 查询会变成私网地址，连接仍只使用首次校验过的公网 IP，
不会再次通过域名解析连接。

主要文件：`app/image_processing.py`。

### 6. 突发日志合并 DOM 更新

原实现每收到一条 SSE 日志就写入 DOM 并读取滚动高度；过滤虽然有节流，插入与滚动仍逐条进行。
现在用 50ms 窗口合并插入、过滤和滚动。待渲染队列与已渲染 DOM 分别最多保留最新 500 条。
清空日志时同时清理队列和定时器，旧消息不会稍后重新出现。

DOM 回归一次发送 700 条日志，验证保留最新 500 条、滚动高度读取不超过两次、
过滤与 HTML 转义正常，并覆盖清空尚未渲染消息的行为。

主要文件：`app/static/console-logs.js`。
